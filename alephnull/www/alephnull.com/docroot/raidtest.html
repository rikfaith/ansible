Simple RAID Tests

Setup

4 Seagate spindles from same drive family. 2 SATA on MB controller, 2 PATA on PCI controller. Asus K8V MB with 2GHz AMD Athlon 64.

Linux 2.6.9-1.667 from FC3.

Tests

Tests used a single 140GB or 130GB pre-zero'd file with 1 or 4 threads. Aggregate reads or writes are 64KB sequential. Random reads or writes are 4K at random locations in the file.

Test deficiencies

Only one thread was used in most tests. This is the case I care about most.

Tests were only run for 5 minutes each.

Results

mdadm chunk size

The chunk size defaults to 64K. Comparisons were done with 4K, 8K, 16K, 32K, 64K, and 128K chunks. The most interesting comparison is with 4K chunks, with provided significant improvements in read performance, without write degradation when using both 1 and 4 threads. These results were confirmed with an ext3fs file system present.

RECOMMENDATION: Use a chunk size of 4K. Do not use an ext3fs stripe size. (This result is unexpected and should be confirmed for RAIDs composed of more than 4 spindles.)

Encryption

Encryption with twofish slows throughput by 30-75%.

ext3fs with noatime

The noatime option appears to improve read performance, but only by about 1-2%. (Inexplicably, it degraded ext2fs aggregate writes by about 2%.)

RECOMMENDATION: Use noatime.

ext3fs with ordered, writeback, and journal

ordered (data before metadata) is the default.
writeback (unordered writes) is expected to be faster.
journal (data is written to journal with metadata) is expected to be slower.

When the journal was stored on the same RAID device as the data, ordered was almost 100% faster than journal for aggregate writes. This is expected, since journal writes the data twice. With the journal option, random reads were about 8% faster than ordered -- this result is unexpected. The writeback option was nearly equivalent to the ordered option.

RECOMMENDATION: When the journal is stored on the RAID device, use data=ordered.

When the journal was stored on a spindle separate from the RAID device, the data=journal option provided at least 100% improvement in all metrics (with 200% improvement in random reads, perhaps because atime was on?). In this case, ordered and writeback were less than 2% improved.

RECOMMENDATION: When the journal is stored separate from the RAID device, use data=journal. (This is unexpected and should be verified by more experimentation.)
